# Правила разработки

## Главное

1. **Работает только на Windows.** Core Audio, `winreg`, `os.startfile`, `MessageBoxW`. На других ОС модули импортируются только ради тестов. Трей, хоткей, popup и настоящий звук проверяются на живой Windows с двумя активными микрофонами.
2. **Слои не смешивать.** Звук - только через `audio_devices` (`Device`, `list_devices`, `get_default_id`, `set_default`), файлы Equalizer APO - только через `equalizer.py`, логика профилей - в `profiles.py`. В `mic_switcher_tray.py` никаких COM-вызовов, SoundVolumeView и прямой записи в папку Equalizer APO.
3. **Пользователь всегда видит результат.** Любое действие и любая ошибка заканчиваются `report(...)`. Одно действие - один popup: вспомогательные функции возвращают текст (как `ensure_default_selection`), склейка - `report_all`.
4. **Логика тестируется.** Новая логика - функция поверх `backend` или чистая функция, с тестом в `tests/`. Новая возможность реализации - в обе (`core.py` и `svv.py`) или явно помечена как только Core Audio.

## Делать

- Новые ключи конфига - в `DEFAULT_CONFIG` и в `config.example.json` одновременно (на это есть тест).
- Изменения выбора Mic 1/2 - через `CONFIG` + `save_config()`, после них `refresh_menu()`.
- Новое действие меню - функция-действие и пункт в `build_menu()` с `menu_action(fn, *args)`.
- Всё про устройства - через `kind` (`MIC`, `OUT`) и слот (`1`/`2`): `get_selected(kind, slot)`, `toggle(kind)`. Без копий функций под микрофон и вывод.
- После смены устройства по умолчанию - `apply_equalizer()` (через `switched`), чтобы пресет переехал на новое устройство.
- Новый хоткей - в `hotkey_bindings()`, регистрация только через `register_hotkeys()`.
- Новые встроенные пресеты - в `equalizer.BUILTIN_PRESETS`, команды в синтаксисе Equalizer APO, с `Preamp` на величину подъёма (тест проверяет формат строк).
- Имена и ID устройств - из кеша `get_capture_devices()`; всё, что должно видеть свежее состояние, - `force=True`.
- В `core.py`: каждый поток - через `_ensure_com()`, COM-объекты создавать в вызове, а не хранить; каждый `PROPVARIANT` освобождать.
- Запись JSON - через `write_json_atomic`.
- Переключение устройства - под `switch_lock`.
- Пути из конфига - через `resolve_path`.
- Тексты интерфейса и лога - на русском.

## Не делать

- Не передавать COM-объекты между потоками и не кешировать их в атрибутах.
- Не включать автообновление для медленных реализаций (`watchable = False`).
- Не менять выбор слотов из-за отключения устройства в `watch_devices`: только меню и popup.
- Не переписывать `config.txt` Equalizer APO: только `ensure_include` и свой `MicSwitcher.txt`.
- Не мутировать `DEFAULT_CONFIG` и списки из `CONFIG` на месте: профили - через `set_profiles`.
- Не трогать `tkinter` вне `PopupManager`.
- Не делать побочных эффектов при импорте модулей: всё в `main()`, `apply_config()`, `open_audio()`.
- Не использовать синтаксис новее Python 3.9 в коде и тестах: тесты гоняются и на системном Python macOS.
- Не класть `SoundVolumeView.exe`, `config.json`, лог и сборки в git.

## Ограничения

| Ограничение | Следствие |
|---|---|
| Equalizer APO | Отдельная установка с правами администратора, устройства отмечаются в его Configurator, нужна перезагрузка. Программы в эксклюзивном режиме обходят обработку. Запись в `config` может потребовать прав, если установщик их не выдал |
| `IPolicyConfig` недокументирован | Может сломаться после крупного обновления Windows; запасной вариант - SoundVolumeView (`audio_backend`) |
| Библиотека `keyboard` | Хоткей не срабатывает в окнах, запущенных от администратора, если MicSwitcher запущен без прав администратора |
| Конфиг и лог рядом с exe | Папка должна быть доступна на запись, `Program Files` не подходит |
| Автозапуск из исходников | В реестр пишется `pythonw.exe` из папки `sys.executable`, если он есть |
| Тесты без Windows | `keyboard`, `pystray`, `comtypes`, `pycaw`, SoundVolumeView подменены; трей, хоткей, реестр, popup и настоящий COM - только ручная проверка |
| Настройки | Применяются при старте или по «Перечитать config.json» |

## Код-стиль

- PEP 8, отступ 4 пробела, без type hints (как в текущем коде).
- `mic_switcher_tray.py` - приложение, `audio_devices/` - звук, `profiles.py` и `equalizer.py` - чистая логика без глобального состояния. Новый крупный блок - отдельным модулем.
- Сообщения пользователю короткие, с конкретикой (имя устройства, текст ошибки).

## Тесты

```bat
py -m unittest -v
py -m unittest tests.test_app.ToggleTests
py -m unittest tests.test_app.ToggleTests.test_fast_repeat_ignored
```

- `tests/stubs.py` - заглушки `keyboard`, `pystray`, Pillow.
- `tests/test_app.py` - приложение на `FakeBackend`: слоты обоих видов, профили, эквалайзер (во временной папке вместо Equalizer APO), хоткеи (`keyboard` - Mock), опрос; время подменено (`self.tick()`).

- `tests/test_audio_devices.py` - `Device`, роли, `open_backend`, `SvvBackend` на фейковом CSV.
- `tests/test_core_audio.py` - `CoreAudioBackend` на фейковых `comtypes`/`pycaw`: свойства, роли, COM по потокам.

## Ручная проверка

1. Удалить `config.json`, запустить: файл создан, слоты Mic и Out выбраны, popup со списком. В логе «Звук: Core Audio» и три «Hotkey ...».
2. `ctrl+alt+m`: микрофон по умолчанию в «Параметры звука» меняется, popup «Переключено на Mic N». В Discord с устройством «По умолчанию» звук идёт с нового микрофона.
3. `ctrl+alt+o`: меняется вывод, звук из браузера и Steam уходит на другое устройство.
4. Зажать хоткей: одно переключение, в логе «Повторное нажатие слишком быстро, пропущено».
5. Подменю «Микрофон» и «Вывод»: «Включить ...», «Выбрать ...»; одно устройство в оба слота - отказ.
6. «Профиль», «Сохранить текущее как профиль...»: окно ввода с именем «вывод + микрофон», после OK профиль в меню с точкой. Сменить устройства, сохранить второй. `ctrl+alt+p` перебирает их, popup «Профиль «...»» с устройствами.
7. Добавить профилю `"hotkey": "ctrl+alt+1"`, «Перечитать config.json»: хоткей применяет профиль, в меню подпись `(ctrl+alt+1)`.
8. Эквалайзер без Equalizer APO: пресет «Бас» - popup «Equalizer APO не найден», в меню «Скачать Equalizer APO».
9. Установить Equalizer APO, отметить наушники и микрофон, перезагрузиться. Пресет «Бас» для вывода - бас слышно сразу; в `config\MicSwitcher.txt` секция с GUID наушников, в `config.txt` строка `Include: MicSwitcher.txt` (одна). Проверить в Editor Equalizer APO, что секция `Device:` относится к нужному устройству.
10. Переключить вывод на колонки: бас переехал на колонки. Сменить вывод в «Параметры звука» вручную: через ~2 с пресет тоже переехал.
11. Микрофон «Голос»: в записи (Discord, «Звукозапись») меньше гула и бубнения.
11a. Микрофон «Шумодав» без плагина: popup «плагин RNNoise не найден», в меню «Скачать шумодав RNNoise». Распаковать релиз в `EqualizerAPO\VSTPlugins`, выбрать снова: в `MicSwitcher.txt` строка `VSTPlugin: Library "...rnnoise_stereo.dll"`, в записи нет клавиатуры и вентилятора. Если Equalizer APO Editor показывает ошибку загрузки плагина - попробовать `rnnoise_mono.dll` через `rnnoise_vst_path`.
11b. «Порог шумодава» 95%: в `MicSwitcher.txt` у строки `VSTPlugin` появился `ChunkData`; в Editor Equalizer APO у плагина порог 0.95; между словами полная тишина. «По умолчанию плагина» - `ChunkData` пропал.
12. Выдернуть USB-устройство: popup «Отключен ...», в меню «не подключен»; вставить - «Подключен ...», выбор прежний.
13. Старый `config.json` с ID вида `Realtek(R) Audio\Device\Микрофон\Capture`: после запуска в нём ID Core Audio, выбор тот же.
14. «Автозапуск» вкл/выкл: значение в `HKCU\...\Run` появляется и исчезает.
15. `"audio_backend": "svv"` с `SoundVolumeView.exe` рядом, «Перечитать»: в логе «Звук: SoundVolumeView», переключение работает.
16. Мусор в `config.json`, перезапуск: popup «config.json поврежден», рядом `config.json.broken`.
17. «Выход»: хоткеи больше не работают, процесса нет.
18. То же для exe из `build.bat` (без установленного Python).
